# Lot Analyzer 48

Скрипт `lot_analyzer_48.py` оценивает ценность каждого лота на горизонте `48` тиков и предлагает рациональные ставки для all-pay аукциона при общем лимите капитала команды `200 RUB`.

## Что делает скрипт

1. Загружает прогноз из `data/forecast.csv`.
2. Считает прибыль базовой системы (`START_SYSTEM`).
3. Для каждого лота считает прибыль системы после добавления лота.
4. Оценивает дельту прибыли:
   - детерминированно (без случайности);
   - через Monte-Carlo (с учетом неопределенности).
5. Выводит таблицу:
   - `value_det`, `value_ev`, `q10`, `q50`, `q90`, `bid_min`, `bid_max`, `bid_rec`.

## Быстрый запуск

Из корня проекта:

```bash
python3 test_game/lot_analyzer_48.py
```

С параметрами:

```bash
python3 test_game/lot_analyzer_48.py --sims 2000 --seed 7 --risk-aversion 0.5 --q10-filter
```

## Входные данные

`forecast.csv` должен содержать минимум 48 строк и колонки для:

- солнца: `sun`/`solar`;
- ветра: `wind`;
- нагрузок: `house`, `office`, `factory`/`plant`.

Берутся первые 48 строк.

## Модель расчета прибыли на тике

Для каждого тика:

1. Формируется спрос:
   - `house_demand = forecast_house * house_count`
   - `office_demand = forecast_office * office_count`
   - `plant_demand = forecast_plant * plant_count`
2. Спрос ограничивается пропускной способностью подстанции `40 MW`.
3. Обслуживание спроса по приоритету: `office -> plant -> house`.
4. Генерация:
   - солнечная: `min(SOLAR_MAX_MW, sun) * solar_count`
   - ветровая: `min(WIND_MAX_MW, wind) * wind_count`
   - ТЭС: до `TPP_MAX_MW * tpp_count`
5. Накопитель:
   - на старте `SOC = 50%` емкости;
   - каждый тик утечка `5%`;
   - разряд покрывает дефицит;
   - заряд идет из избытка ВИЭ с ограничением по скорости, емкости и сети.
6. Если после ВИЭ/накопителя/ТЭС есть дефицит, энергия покупается из сети.
7. Излишки продаются в сеть (опционально включая экспорт ТЭС, если включен `--allow-tpp-export`).
8. Прибыль тика:
   - доход от обслуженной нагрузки по тарифам (`house=3`, `plant=4`, `office=5` RUB/MW);
   - бонус ВИЭ `2 RUB/MW` на использованную ВИЭ-энергию;
   - плюс продажа в сеть `2 RUB/MW`;
   - минус покупка из сети `10 RUB/MW`;
   - минус топливо ТЭС `0.5 RUB/MW`;
   - минус штраф за необслуженный спрос `10 RUB/MW`;
   - минус фиксированный OPEX активов.

Сумма по 48 тикам дает прибыль сценария.

## Как считается ценность лота

Для каждого лота считается:

- `base_profit`: прибыль базовой системы;
- `with_lot_profit`: прибыль системы с лотом;
- `delta = with_lot_profit - base_profit`.

Это и есть экономический эффект лота.

### Детерминированная оценка

- `value_det = delta` на исходном прогнозе без случайных отклонений.

### Monte-Carlo оценка

Для каждой симуляции:

1. Сэмплируется новый сценарий прогноза:
   - `sun` умножается на случайный множитель в диапазоне `[0.5, 1.5]`;
   - `house/office/plant` также в диапазоне `[0.5, 1.5]`;
   - `wind` остается неизменным.
2. Считается `delta_i` между системой с лотом и без лота.

После `N` симуляций:

- `value_ev = mean(delta_i)` — ожидаемая (средняя) ценность лота;
- `std = pstdev(delta_i)` — разброс результата;
- `q10/q50/q90` — квантили распределения `delta_i`.

### Что такое «средняя цена» лота в этом скрипте

В терминах вывода скрипта «средняя цена/ценность» лота — это `value_ev` (столбец `value_ev`), то есть средний прирост прибыли по Monte-Carlo.

Формально:

`value_ev = (delta_1 + delta_2 + ... + delta_N) / N`

Скрипт не пытается предсказать рыночную финальную цену аукциона. Он считает экономически оправданную ценность лота для вашей системы.

## Роль квантилей и риска

- `q10`: нижняя граница, около 10% сценариев будут хуже этого значения.
- `q50`: медиана (типичный сценарий).
- `q90`: оптимистичная зона (лучшие ~10% сценариев выше нее).

Если включить `--q10-filter`, в рекомендации попадут только лоты с `q10 > 0`, то есть даже «плохой» хвост в среднем не убыточный.

Риск учитывается через:

`value_cap = max(0, min(bid_max, value_ev - risk_aversion * std))`

Чем выше `risk_aversion`, тем сильнее штраф за разброс (`std`) и тем ниже допустимая ставка.

## Как формируется ставка (`bid_rec`)

1. Для каждого лота считается предварительная ставка:

`raw_bid = alpha * value_cap`

2. Ограничения:
   - `raw_bid` не может быть выше `value_cap`;
   - все ставки масштабируются пропорционально, чтобы суммарно уложиться в `TEAM_CAPITAL - reserve`.
3. Если итоговая ставка меньше стартовой цены лота (`start`), ставка по этому лоту обнуляется.

Итог:

- `bid_max` — верхняя экономическая граница (`max(0, min(200, value_ev))`);
- `bid_rec` — практическая ставка с учетом бюджета, риска, `alpha`, `reserve` и фильтра по `q10`.

## Аргументы CLI и влияние

- `--csv`: путь к CSV прогнозу.
- `--sims`: число Monte-Carlo симуляций. Больше симуляций -> стабильнее оценки, медленнее расчет.
- `--seed`: фиксирует случайность для воспроизводимости.
- `--allow-tpp-export`: разрешает продавать избыток ТЭС в сеть.
- `--reserve`: резерв капитала, который не участвует в ставках.
- `--alpha`: агрессивность ставки от `value_cap`.
- `--risk-aversion`: штраф за риск через `std`.
- `--q10-filter`: отсекает лоты с `q10 <= 0`.
